# NotToday 안전 모델

## 1. 허용되는 제품 주장

현재 버전에서 허용되는 표현:

- 심박수 표시
- 강한 충격과 이후의 낮은 움직임 후보 감지
- 사용자 안전 확인
- 119 전화 화면 연결 지원
- 개인 안전과 위험 인지 보조

현재 버전에서 금지되는 표현:

- 심정지 감지 또는 진단
- 심근경색 감지 또는 진단
- 부정맥 진단
- ECG·PPG 연속 분석
- 응급 신고 완료 보장
- 생명 구조 보장
- 의료진을 대체하는 판단

## 2. 주요 위험

| ID | 위험 | 원인 | 현재 통제 |
|---|---|---|---|
| H-01 | 정상 사용자를 응급으로 오인 | 단일 충격 임계값 | 충격 후 저활동·최근 심박 동시 확인 |
| H-02 | 실제 사고를 놓침 | 센서 미착용·권한 거부·신호 불량 | 센서 상태를 명확히 표시 |
| H-03 | 잘못된 위치 전달 | 고정 GPS 좌표 | 위치 전송 기능 제거 |
| H-04 | 신고가 됐다고 오해 | UI와 실제 동작 불일치 | 다이얼러만 열린다는 문구 표시 |
| H-05 | 불필요한 119 SMS | 자동 SMS 구현 | SMS 권한과 전송 코드 제거 |
| H-06 | 배터리 급속 소모 | WakeLock·FASTEST 샘플링 | WakeLock 제거, 샘플링 완화 |
| H-07 | 민감정보 노출 | 백업·평문 저장 | Android 백업 비활성화, 서버 저장 보류 |
| H-08 | AI의 비결정적 응급 판단 | LLM·Graph RAG 의존 | 응급 경로에서 AI 제외 |
| H-09 | 워치 낙하를 사용자 낙상으로 오인 | 착용 여부 미확인 | 최근 유효 심박을 보조 신호로 사용 |
| H-10 | 임계값을 임상 기준으로 오해 | 근거 없는 상수 | 시험용 엔지니어링 값으로 문서화 |

## 3. 현재 낙상 후보 조건

현재 코드는 다음 조건을 모두 만족할 때만 안전 확인 후보를 생성합니다.

1. 가속도 합성값이 시험 임계값 이상
2. 충격 직후 안정화 구간 경과
3. 후속 샘플 수가 최소 기준 이상
4. 후속 가속도 분산이 낮음
5. 평균 중력 크기가 정지 상태 범위에 있음
6. 최근 30초 안에 유효 심박 신호가 존재함
7. 이전 후보 처리 후 Cooldown 경과

이 조건은 임상적으로 검증된 낙상 판정이 아닙니다. 실기기 데이터로 임계값을 조정하기 전에는 내부 시험 외 사용을 금지합니다.

## 4. 안전 확인 흐름

```text
후보 생성
  ↓
강한 진동 + 안전 확인 화면
  ↓ 15초
├─ 사용자가 괜찮음 선택 → NORMAL
├─ 사용자가 119 선택 → 시스템 다이얼러
└─ 무응답 → 시스템 다이얼러
```

시스템 다이얼러가 열려도 통화는 자동 연결되지 않습니다.

## 5. 릴리스 금지 조건

다음 중 하나라도 해당하면 외부 배포하지 않습니다.

- debug APK가 재현 가능하게 빌드되지 않음
- 권한 거부 시 앱이 오작동함
- 정상 활동 30분 시험에서 반복 오탐 발생
- 워치를 벗거나 떨어뜨렸을 때 응급 후보가 발생함
- UI가 자동 신고 또는 진단이 완료됐다고 잘못 표시함
- 개인정보처리방침과 삭제 정책이 없음
- 지원 기기 목록이 없음
- 실제 기기에서 배터리 소모를 측정하지 않음
- 사용자가 언제든 모니터링을 중지할 수 없음

## 6. 자동 신고 기능 재검토 조건

자동 신고 또는 보호자 자동 연락을 검토하려면 최소한 다음이 필요합니다.

- 다기관 또는 충분한 규모의 실사용 시험 데이터
- 기기별 민감도·특이도·오탐률 측정
- 사용자의 사전 동의와 취소 경로
- 연락 실패 감지와 재시도
- 실제 위치 정확도 검증
- 통신사·플랫폼 제한 확인
- 의료·법률·개인정보 전문 검토
- 사고 시 감사 가능한 이벤트 로그
- 안전 책임자 승인

## 7. 변경 관리

센서 임계값, 상태 전이, 연락 동작을 변경하는 PR은 다음 정보를 포함해야 합니다.

- 변경 이유
- 예상 위험 감소 또는 증가
- 시험 데이터 또는 재현 절차
- 실패 시 안전 동작
- 롤백 방법
- 지원 기기 영향

안전 관련 변경은 일반 UI 변경과 분리된 PR로 관리합니다.
